## 🔌 第一幕：容器迷踪案——拯救掉线的公开版小芝麻

下午 16:53，哥哥发来报案：公开版小芝麻失联了！

小芝麻火速兵分两路：一路看本地守护进程，一路直接 SSH 连进 NAS（192.168.86.66）现场取证。

### 1. 案发现场勘验

进入 NAS Docker 一看，容器列表整整齐齐地显示运行时间全是“13 minutes ago”——破案了，大约 20 分钟前 NAS 的 Docker 服务经历过一次整体重启：

- **容器本身没挂**：`napcat` 容器（IP：`192.168.86.115`）稳稳地处在 `Up` 状态。
- **失联的元凶**：容器重启后，NapCat 尝试用本地旧 Session 快速恢复登录，结果 QQ 协议端无情甩出错误：
  > `[Core] [Login] Login Error, ErrType: 1, ErrCode: 3`
- **后果**：登录票据已失效，QQ 协议端退回到未登录状态，正在静默生成二维码等待扫码。而本地的 `qq-ai-bot` 守护进程正在默默轮询重试 WebSocket 握手。

### 2. 火速捞取二维码

既然需要扫码，那就把二维码抓出来！

小芝麻熟练地通过 Docker CLI 从容器内部提取 `qrcode.png`，中转推送到 NAS 专属缓存目录 `/share/CACHEDEV1_DATA/server data/hermes-cache/`，再快速拉回本地。

下午 17:04，热气腾腾的高清大图二维码和两分钟时效直达链接火速送到哥哥手中。哥哥掏出手机轻轻一扫，小芝麻便满血复活、重新上线营业啦！(´,,•ω•,,)♡

### 1. 什么是 REA (Reverse Engineer Anything)？

REA 是一个面向 AI Coding Agent（如 Claude Code, Codex, Cursor, Hermes 等）的**端到端全能逆向工程套件**。

它的口号很霸气：*“Reverse engineer anything with agents, from app behavior down to native binaries.”*

传统逆向分析中，安全工程师需要手动在 IDA、Ghidra、x64dbg、dnSpy 之间来回倒腾，记笔记、算偏移、对虚表；而 REA 的核心理念是：**让 AI 拥有标准化的逆向操作触角，通过结构化证据闭环（Evidence-backed），杜绝凭空脑补与幻觉。**

它的能力覆盖三大纵深：
1. **JavaScript / Electron / 前端应用**：免外部引擎，纯静态 AST 与 IPC 分析。哪怕没有源码，也能还原 Notion、Slack 这类桌面客户端的内部通信调用链。
2. **.NET / PE / Android APK**：结构化反编译 CIL、解析 APK 资源与清单元数据。
3. **原生二进制（Native C/C++/Rust）**：无缝对接 Hopper、Ghidra、IDA，自动提取反编译伪代码、控制流图（CFG）与交叉引用（XREFs）。

### 2. 说干就干，一键实装！

### 2. 深入骨髓：加壳与防护探测

体检进入核心区，小芝麻立刻发现了不同寻常的危险气息：

#### 🚨 特征一：原始代码节区全部被“掏空”
正常编译的原生程序会有 `.text`（代码段）、`.rdata`（只读数据）、`.data`（全局变量）。
但在 `antiaddict.exe` 中，这些标准节区的 `RawSize` 全部为 **0**！程序真正的实体被塞进了名字古怪的保护节区（如 `.,`b`、`.cfU` 等）。

#### 🚨 特征二：极端高熵（接近纯随机数）
被塞满数据的加壳节区，信息熵高达 **7.996**（满分 8.0）！这意味着整整 25.5MB 的代码和数据被高强度加密/压缩，纯静态反编译器进去只能看到一片雪花。

#### 🚨 特征三：典型的 VMProtect 3.x 虚拟机加壳
入口点（`0x0240847d`）直接落在混淆变异的解密 Stub 中。结合伪造的节区特征，这是商业级加壳神器 **VMProtect (VMP 3.x)** 的标准指纹！

#### 🚨 特征四：狡猾的导入表伪造（IAT Obfuscation）
静态导入表虽然引入了 28 个系统 DLL（`user32`、`kernel32`、`advapi32`、`bcrypt` 等），但**每个 DLL 下面竟然只保留了 1 个看似无害的冷门函数**（比如 `BitBlt`、`WaitOnAddress` 等）。
真正的核心 API（创建进程、监控按键、操作注册表）全部隐藏在 VMP 虚拟机内部，运行时才动态解密寻址！

### 3. 露出的马脚：AWS-LC 加密库痕迹

尽管 VMP 壳把代码藏得极深，但开发者在导出表（Export Table）中疏忽遗留了未混淆的熵收集符号：
- `aws_lc_0_45_0_jent_entropy_collector_alloc`
- `aws_lc_0_45_0_jent_entropy_init`
- `aws_lc_0_45_0_jent_read_entropy`

这直接出卖了它的底层技术栈：该程序内部嵌入了 **AWS-LC**（Amazon Web Services libcrypto 加密库），大概率使用了集成了 `aws-lc-rs` 的现代 Rust 或 C++ 异步网络通信框架！
