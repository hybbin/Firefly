## 📦 第一幕：掀开面纱——这不是山寨套壳，是正牌纯原生 Compose

初见应用基础信息，各项参数就已经透露出一股不同寻常的专业极客味道：

- **应用名**：石头影视（服务端识别名：石头影院）
- **真实包名**：`com.zhou.embyplayer`
- **体积大小**：约 49.7 MB
- **加壳状态**：未加任何第三方商业壳（梆梆、乐固、爱加密等），全裸奔架构

通常市面上的野鸡影视 App，为了防逆向和防抓包，动辄套上厚重的加壳防护，内部代码往往是老旧的混淆 Java 堆砌。但这款 App 的代码结构清晰利落：

### 1. 纯粹的现代化架构
它通篇基于 Google 当前力推的 **Jetpack Compose + Kotlin 协程（Coroutines/Flow）** 响应式构建。没有陈旧的 XML 布局堆叠，UI 逻辑全部用声明式代码编排，状态流转干净利落。

### 2. 双端自适应：为大屏电视而生
在 `AndroidManifest.xml` 的启动声明中，赫然配置了：
```xml
<category android:name="android.intent.category.LEANBACK_LAUNCHER" />
```
这意味它不仅能在哥哥的手机上触控滑屏，更是一台天生适配 **Android TV / 电视盒子**的专属播放端！支持遥控器方向键无缝焦点导航，界面按大屏交互规范精心缩放。

## 🎬 第二幕：双播放内核的野心——MPV + ExoPlayer 本地硬解直出

深入解码层，小芝麻发现了这款客户端最硬核的心脏设计。

它没有走常规 Emby 客户端“遇到高码率就请求服务端转码”的偷懒路线，而是内置了两套强大的播放引擎：

1. **MPV 引擎（`libplayer.so`）**：  
   底层通过 JNI 引入高度优化的 C/C++ 原生 MPV 播放器内核。MPV 在高清极客圈子里声名显赫，以极限画质还原和色彩管理著称；
2. **Google ExoPlayer**：  
   Android 生态中最稳定的系统级流媒体引擎，作为稳健后备支持。

```
                  ┌──────────────────────────────┐
                  │      石头影视 UI 交互层        │
                  │   (Jetpack Compose + Flow)   │
                  └──────────────┬───────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
       ┌──────────────────┐            ┌──────────────────┐
       │   ExoPlayer 引擎  │            │   MPV 原生内核   │
       │  (流媒体自适应分片) │            │ (libplayer.so硬解)│
       └──────────────────┘            └──────────────────┘
                 │                               │
                 └───────────────┬───────────────┘
                                 ▼
                     4K HDR / 原画无损直出
```

### 为什么执着于“本地硬解”？
普通的 Emby 私有服，如果遇到 4K HEVC、高规格音频或特殊封装格式，若客户端算力不足，服务端 CPU/GPU 就会瞬间飙到 100% 冒烟转码，画质损耗不说，还容易卡成幻灯片。

而这款 App 的逻辑非常霸道：**全部压给播放端本地硬件解码芯片！**  
不仅如此，代码中还内嵌了对 `.strm` 直链与切片源的高速嗅探解析，甚至为了防止电视端字幕乱码或缺字，在资源包里贴心地内置了 `subfont.ttf` 字体文件。画质不缩水、色彩无损耗，实乃观影强迫症患者的福音～ヽ(>∀<☆)ノ
