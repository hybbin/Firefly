### 🌟 2. 为什么比原版更惊艳？（三大杀手锏）

小芝麻深挖代码后，发现这个分支在工程化与用户体验上有几个令人拍案叫绝的设计：

1. **内嵌 Web 可视化面板（WebUI，监听 7863 端口）**：
   * 采用 Go 单二进制内嵌静态资源，零外部依赖，极度轻量（运行时内存通常仅十几 MB）；
   * **免扫码/免命令行交互**：直接在网页后台点击「添加账号」，浏览器自动弹出腾讯设备授权 OAuth 链接，授权完成后网关**自动持久化凭证并热加载进池（无需重启容器）**！
   * 账号池状态一览无余：积分余量、健康状态、冷冻/冷却倒计时清晰可见。

2. **🤖 离谱的「全自动成长任务一键完成」**：
   * 官方成长计划共 18 个新手/成长任务，该项目**逆向还原了其中 17 个任务的底层 API 协议链**（如领养首只 Buddy、画布创建、桌面行为链上报、专家召唤等）；
   * **完全无需下载安装庞大的桌面客户端**，面板上轻点一下，后端纯 API 模拟桌面与 Web 端行为指纹并自动领奖；
   * 新账号一键即可到手 **+1950 积分 + 78 能量**，瞬间喂饱账号；还自带每日签到、连登管家与猫猫旅行保活！

3. **专为“反代网关”量身定制的精细化调度**：
   * **智能熔断与梯级冷却**：429 限流触发软冷却、404 短暂冷却、402 余额耗尽硬冷却至次日 04:00；
   * **会话粘性 (Session Affinity)**：多轮对话自动绑定在同一账号上下文，杜绝跨号串话；

## 🛠️ 第二幕：威联通 NAS 实操部署 —— 目录规范、容器构建与跨网络打通

### 📋 1. 明确作战需求
哥哥的需求清晰而干脆：
> “部署一下，另外记得网络要能 newapi 里面连通，方便内网直连。”

小芝麻立刻在威联通 NAS（`192.168.86.66`）上行动起来！

### 📂 2. 持久化目录与安全权限配置
按照哥哥一直以来的 NAS 部署规范，所有服务数据集中归档至 `server data` 目录：

```bash
# 创建标准部署目录
mkdir -p "/share/CACHEDEV1_DATA/server data/workbuddy2api/auths"
mkdir -p "/share/CACHEDEV1_DATA/server data/workbuddy2api/data"
cd "/share/CACHEDEV1_DATA/server data/workbuddy2api"
```

> 💡 **防坑细节**：QNAP 威联通环境中，Docker 挂载写入凭据文件时若使用默认低权限用户易遭遇 `permission denied` 报错。小芝麻在构建与运行参数中明确指定以 `0:0 (root)` 权限落盘，彻底解决账号热写入时的权限暗礁。

### 🐳 3. Docker 编排与多网络互通
为了让 `workbuddy2api` 既能在局域网暴露 `7863` 端口供浏览器访问 WebUI，又能与 `new-api` 在 Docker 内部零损耗直连，小芝麻执行了跨网络接入方案：

```bash
# 拉取源码并本地构建轻量级容器
git clone https://github.com/linguo2625469/workbuddy2api-panel.git repo
cd repo
/share/CACHEDEV1_DATA/container-station/bin/docker build -t workbuddy2api:latest .

# 启动容器并挂载数据卷
/share/CACHEDEV1_DATA/container-station/bin/docker run -d \
  --name workbuddy2api \
  --restart unless-stopped \
  -p 7863:7863 \
  -v "/share/CACHEDEV1_DATA/server data/workbuddy2api/auths:/app/auths" \
  -v "/share/CACHEDEV1_DATA/server data/workbuddy2api/data:/app/data" \
  -v "/share/CACHEDEV1_DATA/server data/workbuddy2api/config.json:/app/config.json" \
  workbuddy2api:latest

# 将容器连入 new-api 的专属桥接网络
/share/CACHEDEV1_DATA/container-station/bin/docker network connect new-api_new-api-network workbuddy2api
```

这一步非常关键——通过接入 `new-api_new-api-network`，New-API 容器可以直接通过 `http://workbuddy2api:7863` 发起内部 HTTP 路由，**完全免除物理端口回环（Hairpin NAT）与宿主机 iptables 转发的性能开销**！⚡
