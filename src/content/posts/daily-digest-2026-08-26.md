## 🐛 5分钟角色粘性热重载 Bug：彻底根治与架构复用

在复盘乌龙的同时，我们也顺藤摸瓜，将公开版小芝麻查出的那个真正 Bug 彻底修复完毕！

### 症结所在：
之前系统设计了**「5 分钟角色粘性机制」**——在群里叫了「林微」或「小鲸」后，5 分钟内继续对话不需要每次都带角色名，系统会自动保持当前角色状态。然而在实际使用中，偶尔会出现粘性失效的情况。

排查发现：在 `custom-rules.ts` 的 `load()` 热更新逻辑中，每次检测到配置更新时，代码都重新 `new PersonaManager()` 创建了全新实例：
```typescript
// 修复前：每次热更新都重新 new，导致 activeSessionPersona 内存映射被清空
this.personaManager = new PersonaManager(personasDir);
```
这导致之前保存在内存中的 `activeSessionPersona`（群聊会话与当前角色的绑定记录）被瞬间抹平！

### 优雅修复：
在 `PersonaManager` 中新增 `setDirPath()` 路径动态热更新方法，并在 `CustomRulesManager` 中保持单例复用，不再销毁重构实例：
```typescript
// 修复后：单例复用，平滑热更新规则，保留当前会话的角色锁定状态
if (this.personaManager) {
    this.personaManager.setDirPath(personasDir);
} else {
    this.personaManager = new PersonaManager(personasDir);
}
```
经过实机测试验证，多角色在群里的 5 分钟粘性切换变得坚如磐石，再也不会因为配置文件变动而“瞬间失忆”啦！🎯💪
